# DuoFrost 2.5.0-alpha.1

The first development build toward 2.5.0 introduces Smart Scenes. It is a testing
build, not the final 2.5.0 release. The published releases remain available.

[Download the signed APK](https://github.com/Tufein/DuoFrost/releases/download/v2.5.0-alpha.1/DuoFrost-2.5.0-alpha.1.apk) ·
[Release notes, source and checksums](https://github.com/Tufein/DuoFrost/releases/tag/v2.5.0-alpha.1).
Published as a pre-release on 10 October 2026. Back up your settings before
installing an alpha.

## Try Smart Scenes

1. Open **Smart Scenes** from the lighting dashboard or Device settings.
2. Save a lighting preset if you have not created one yet.
3. Add a scene: choose a preset, or choose **only limit brightness**.
4. Choose the matching apps or games, hours, weekdays, battery level or power source.
5. Enable Smart Scenes and start lighting normally.

All conditions in a scene must match. Exact app profiles take precedence over
general scene rules. Between matching scenes, higher priority wins; at equal
priority, the first listed matching scene wins. Separate brightness-only rules
combine using the lowest limit. Device-wide brightness limits and mute still apply.

For example, create a **Night dimming** rule that only limits brightness to 20%
from 22:00 until 07:00. It keeps the chosen preset and follows the starting day's
weekday across midnight.

## App groups and temporary choices

Create a group for emulators, favourite games or media apps. Groups let you choose
apps yourself when Android does not identify them as games. Game and app-group
rules need Usage Access; time and battery rules work without it. Matching happens
at the Android app level, not at the level of an individual ROM inside an emulator.

A temporary scene holds a chosen preset for 15, 30, 60 or 120 minutes. Resume
automatic choices early with the **Resume** button. After the hold ends, DuoFrost
checks the current rules again. Stop clears the hold, and it does not survive a
device reboot. Editing or enabling rules never starts stopped lighting.

The dashboard shows the active scene reason. Charging indicators, low-battery
alerts and plugin lighting retain their existing behaviour. Capture effects may
ask for permission when a new capture session is required.

## Preset compatibility

Saved presets now have stable internal identities. Renaming a preset does not
break its new scene rules. Older presets receive identities without changing
their colours, images or plugin ownership. Old preset imports remain supported;
imported identity collisions receive a new identity.

Full backups with Profiles selected include scene rules and app groups. Temporary
holds and Android permission grants are not transferred. Keep a full backup when
testing an alpha build.

## What comes next

The next development stage adds favourites and collections, animated previews,
selective import and undo. General scene transitions and creative palette tools
follow the [2.5.0 roadmap](roadmap-2.5.0.md). Different effects per stick remain a
prototype candidate, not a feature of this alpha.

## Testing builds

A production-signed alpha can update 2.1.0 or 2.3.0 in place using the same release
key. A debug APK uses a separate application ID and installs alongside production;
its settings are separate. Run one LED controller at a time on an AYN device.

Automated tests cover scene decisions, preset identities and Android interaction.
Physical LED output and firmware behaviour require AYN hardware testing before
the final release.
